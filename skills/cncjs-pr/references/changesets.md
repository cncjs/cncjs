# Changesets

The published package is `cncjs`. `src/package.json` describes the desktop app
and is generated by `yarn package-sync`, not a second changeset package.

## When a changeset is required

Add a changeset for a change that affects users of the published package:

- features, fixes, performance work, and behavior changes;
- dependency or build changes that alter the shipped package;
- runtime-support or packaging changes.

Do not add one for docs-only, test-only, CI-only, or purely internal repository
work. When unsure, inspect recent merged changesets and the release PR rather
than guessing.

## File

Create one file per change in `.changeset/`:

```
.changeset/<slug>.md
```

Use a short descriptive slug. When the PR number is known, the repository also
accepts `cncjs-pr-<number>-<slug>.md` or `cncjs-pr-<number>.md`; current examples
include `watch-file-streaming-upload.md`,
`cncjs-pr-1015-watch-file-rename-delete.md`, and `electron-builder-26-rpm.md`. Do
not invent a PR number or create a placeholder file merely to obtain one.

## Format

```markdown
---
"cncjs": patch
---

fix(api): reject a watch-directory name containing a path component

The handler now refuses a name with directory components instead of stripping
it, so the operation cannot escape the watched directory. The response is 400
and no file is written.
```

- The frontmatter has exactly the package and bump type.
- The first body line is a conventional-commit summary
  (`<type>(<scope>): <description>`) matching the PR.
- Follow it with a blank line and enough prose for a release note: what changed,
  why, and any compatibility or migration consequence.
- Keep one changeset per logical change; do not add a second file for the same
  PR.

## Bump type

| Bump | Use for |
| --- | --- |
| `patch` | Bug fixes, internal corrections, build/packaging fixes, dependency updates that preserve behavior |
| `minor` | New features, new endpoints or options, new user-visible behavior, and runtime/packaging support changes |
| `major` | Breaking changes to public APIs or configuration that require migration; confirm the intended release line before using it |

Release versions and `CHANGELOG.md` sections are generated from these entries by
Changesets. Do not hand-edit `package.json` versions, generated changelog
sections, or delete changesets in a feature PR; see `cncjs-version`.

## Completion checklist

- [ ] A changeset exists for a published-package change, with the correct
      package, bump, and conventional summary.
- [ ] One file per logical change; no invented PR number.
- [ ] No version, changelog, lockfile, or release metadata was hand-edited.
