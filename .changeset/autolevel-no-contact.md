Add an autolevel option to survive grid points with no contact: probe with G38.3, retry at nearby spots, and skip the point (interpolating it later) instead of alarming and killing the run. Probing is now dispatched one point at a time -- for every run, with the option on or off -- because deciding between advancing, retrying beside the point and skipping it needs the result of the probe that just finished, and G-code has no conditional for that. Every way a run can die therefore ends it with an error the widget reports instead of leaving it hanging: an alarm, a probe line the controller rejects, a controller reset, a probe area with no points in it, the controller already being in alarm state, or a second run started while one is live. Measurements taken before a run dies are kept, on the server too, so a partial map survives a page reload and can still be applied.

Because a run now advances only from a probe result, several ordinary actions used to break it silently or noisily, and no longer do. Starting or resuming a G-code program during a run is refused, instead of starving the probing dispatch and hanging the widget on its progress bar forever. `error:N` codes that only a `$` command or a `$J=` jog can raise (jogging is enabled while the machine is in Run state, and the Grbl widget's Refresh sends `$#` and `$$`) no longer end a healthy run. A `[PRB:]` line identical to the one already consumed is a replay of the stored probe parameter -- what `$#` dumps -- and is ignored rather than recorded as the next point's height, which shifted the whole map by one node. A Test Probe is refused while a run is live, and its own result can no longer be claimed by a run started while it is still descending. A refused start is reported as a refused start, so it no longer tells the client that owns the live run that the run stopped. The setup form rejects a probe area whose end is at or before its start, an End Z at or above Start Z, and a feedrate of zero.
