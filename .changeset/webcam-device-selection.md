fix(webcam): use the selected camera and switch cameras without remounting

The Webcam component requested the camera with the legacy `{ optional: [{ sourceId }] }` constraint, which current browsers can ignore, so the first camera in the list was used no matter which one was selected in the Webcam Settings. It now uses `navigator.mediaDevices.getUserMedia` with the standard `{ deviceId: { exact } }` constraint, keeping the legacy callback API as a fallback for browsers without `mediaDevices`. The stream was also requested only when the component mounted, so changing the camera while the webcam was on had no effect; the component now stops the current stream and requests a new one whenever the `video` or `audio` prop changes. If the selected camera is unavailable (for example unplugged), it falls back to the default camera and logs a warning instead of showing nothing, and "Automatic detection" still uses the browser's default camera. A stream that arrives after a newer request, or after the last Webcam component has unmounted, is stopped rather than left running, so the camera is released when the widget is disabled while a request is pending. This also removes the debug `console.log` that printed the device id, drops the `enumerateDevices` step that always picked the first video input, and guards the unmount cleanup against removing the wrong instance.
